# 统一账号、产品与权益签名契约（冻结版 v1）

适用服务：`https://anyq.site`，以及复盘虾、漫剧虾、运营虾三个桌面客户端。本文件是账号、付款和权限判断的唯一规范；与任何口头约定或客户端旧逻辑冲突时，以本文件为准。

## 1. 不可变的安全原则

1. **服务端数据库是权益唯一真相源。** 只有服务端在验证微信支付官方回调后，才可以写入 `user_products`。客户端、网页、订单轮询和自定义请求都不能开通、续期或修改任何产品。
2. **桌面端只以有效签名载荷授权。** HTTP JSON 根节点的 `user`、`products` 仅可用于过渡期展示；客户端不得用它们解锁功能，必须验签 `account_license.payload` 后使用载荷中的字段。
3. **高价值服务每次二次鉴权。** 课程下载、云端分析、导出和受限接口必须校验服务器 session 与实时 `user_products`，不能只因客户端已经验过一次签名就放行。
4. **签名不是登录凭据。** `account_license` 可在短有效期内被读取和重放，但不能用于登录、创建订单、调用付款回调或换取 session。
5. **客户端本地防护只提高成本。** 私钥永不出服务器；客户端只内置公钥。Nuitka、Electron 压缩和完整性清单不能替代服务端鉴权。

## 2. 固定产品目录

| `product_id` | 名称 | 价格（分） | 周期 | 产品权益 |
|---|---:|---:|---|---|
| `replay_shrimp` | 复盘虾 + 运营杀招教程 | 249900 | 365 天 | `livewatch` |
| `comic_shrimp` | 漫剧虾 + 漫剧精品课程 | 79900 | 365 天 | `comic_course` |
| `operation_shrimp` | 运营虾 | 79900 | 365 天 | `operation_course` |

价格、名称、周期和订单快照以服务端 `GET /api/pay/plans` 为准。网页只渲染该接口，不得自行硬编码金额、旧月度档位或产品 ID。

产品之间严格隔离：购买或续期一个产品，只能更新同一 `(user_id, product_id)` 的 `user_products` 行，绝不能覆盖或解锁另一个产品。

## 3. 账号响应与签名权益包

登录成功和 `GET /api/auth/me` 在登录状态下都返回以下结构。根节点兼容字段将在所有三个客户端升级后删除；它们不是授权来源。

```json
{
  "ok": true,
  "user": { "id": 1, "phone": "13800138000", "role": "regular" },
  "products": [],
  "server_time": "2026-07-14T00:00:00.000Z",
  "account_license": {
    "schema": "anyq.account-license.v1",
    "alg": "Ed25519",
    "key_id": "account-v1",
    "payload": "base64url(UTF-8 JSON bytes)",
    "signature": "base64url(Ed25519 signature over the exact payload bytes)"
  }
}
```

`payload` 解码后的固定字段如下。所有时间均为 Unix 秒，`signed_until` 最长为签发后 10 分钟；服务器可缩短，不得延长。客户端验签时必须先对**原始解码字节**验签，验签成功后才解析 JSON，禁止“解析后重新序列化再验签”。

```json
{
  "typ": "anyq.account-license.v1",
  "iss": "https://anyq.site",
  "aud": "replay_shrimp",
  "issued_at": 1783987200,
  "signed_until": 1783987800,
  "server_time": "2026-07-14T00:00:00.000Z",
  "user": { "id": 1, "phone": "13800138000", "role": "regular" },
  "products": [
    {
      "product_id": "replay_shrimp",
      "name": "复盘虾 + 运营杀招教程",
      "price_cents": 249900,
      "duration_days": 365,
      "status": "active",
      "expires_at": "2027-07-14T00:00:00.000Z",
      "entitlements": ["livewatch"]
    }
  ]
}
```

规则：

- `key_id` 必填。客户端按内置的“允许公钥集合”选取公钥；未知算法、未知 key、重复字段、非预期类型或验签失败，一律视为未登录/无权益。
- `iss` 必须完全等于 `https://anyq.site`；`typ`、`alg` 必须完全匹配；本机时间超过 `signed_until` 时立即失效。客户端应允许不超过 120 秒的服务器时间偏差，并在下次刷新前不离线延长授权。
- `aud` 是签发给哪个客户端产品的受众标识，必须等于当前客户端的固定 `product_id`。它不是用户可购买的产品，也不能由前端任意传值后成为授权依据。
- 每个客户端只检查自己的固定组合：复盘虾 `replay_shrimp + livewatch`，漫剧虾 `comic_shrimp + comic_course`，运营虾 `operation_shrimp + operation_course`。还必须满足 `status === "active"` 且 `expires_at` 未过期。
- 一个载荷可包含用户的全部 `products`，但客户端不得据此解锁其他产品。`role` 默认 `regular`，角色本身不授予任何付费权益。
- `device_hash` **不进入 v1 的授权判断**。未有服务端设备登记、上限、换机和撤销流程前，客户端提供的 hash 可伪造，只能作为诊断信息。以后启用设备绑定时必须单独升级为 v2。

## 4. 三类凭据严格分离

| 名称 | 用途 | 有效期/存储 | 绝对禁止 |
|---|---|---|---|
| 服务端 session | 登录后的服务器请求鉴权 | HTTPS；网页用 `HttpOnly`、`Secure` Cookie；桌面端仅经系统保护的本地存储保存 | 置入日志、URL、渲染进程或导出文件 |
| `account_license` | 客户端短时、离线可验证的权益快照 | 签发后最多 10 分钟；客户端只保存到其失效 | 登录、创建订单、支付确认、延长会员 |
| `web_handoff` | 客户端跳转官网的一次性登录交接 | 单次、60 秒、服务端只存摘要；票据只在 URL fragment | 用作权限许可证、付款 nonce 或长期 session |
| payment nonce / 订单号 | 支付流程关联和幂等 | 仅服务端订单上下文 | 作为“支付成功”或“开通权益”证明 |

## 5. 支付与权益写入流程

1. 已登录用户选择 `GET /api/pay/plans` 返回的 `product_id`；服务器创建待支付订单，并快照产品名称、金额、期限、权益和用户 ID。
2. 客户端只展示二维码和轮询**自己的**订单状态；不可提交 `paid`、`success`、产品权益或到期时间。
3. 微信官方服务器回调是唯一成功来源。服务端必须验证回调签名与平台证书、商户号、应用 ID、`out_trade_no`、交易号、金额、币种和成功状态。
4. 在一个数据库事务中，以唯一交易号和订单状态实现幂等：将订单置为成功，并只续期该订单对应的 `user_products` 行。重复回调不得重复加期。
5. 返回给客户端的“支付成功”只是展示结果；服务器重新签发权益包。任何一个字段不一致均拒绝回调并记录脱敏审计日志。

## 6. 变更权限与验收门槛

从本规范发布起，冻结产品 ID、支付回调、`user_products` 表、签名字段和服务端授权规则。

- **远端账号服务负责人**：唯一可修改 `server.js` 的账号、支付、签名、订单、数据库迁移和密钥轮换逻辑；每次变更必须提供迁移、回滚和测试证据。
- **三个客户端负责人**：只能消费本规范，负责公钥验签、产品隔离、失败降级和 UI；不得修改远端支付回调、私钥、产品目录或自行引入旧字段兜底。
- **协议变更**：只能新增可选字段；影响字段必须发布 `v2`，保留 v1 至三个客户端完成升级。不可“悄悄改同名字段”的含义。

所有客户端发布前必须通过：

1. 合法签名、篡改 `products`、篡改 `signed_until`、错误公钥、未知 `key_id`、过期签名的验签测试；后五种均不可解锁。
2. 三个交叉产品测试：其他两款产品的有效权益不能解锁当前客户端；空 `products` 不能回退到 `membership_expires_at`、`is_member` 或能量余额。
3. 服务器支付回调的金额不符、产品不符、重复交易号、伪造签名、非本人订单访问测试。
4. 禁止在源代码、安装包、日志和 URL 中出现私钥、短信验证码、Cookie、长期 session 或支付密钥；客户端仅允许内置公钥和 `key_id`。

## 7. 实施状态与剩余发布门槛（2026-07-14）

已完成：远端 `account_license` 已包含 `schema`、`alg`、`key_id`、`iss`、`aud` 和最多 10 分钟的签名有效期；受众只从白名单 `X-Product-Code` 请求头读取，`device_hash` 不再进入授权载荷。远端登记的公钥已校正为与实际签名私钥配对的公钥。

复盘虾已完成 v1 适配：只保存经验证的签名包与受保护 session，旧 v1 本地会话只能用于刷新新签名，不能继续授权；篡改、过期、未知密钥、错误受众和跨产品权益均有自动化测试。

发布前仍需完成：

1. 漫剧虾、运营虾按相同规范完成验签及跨产品拒绝测试；它们不得复制复盘虾以外的产品常量。
2. 用真实手机号完成一次“登录 → `/api/auth/me` 刷新 → 本地验签 → 网页交接 → 退出”的非生产金额端到端验收；生产私钥不得用于测试夹具，也不得导出到客户端。
3. 高价值云端接口继续执行服务器 session + 实时 `user_products` 二次鉴权；不要把短期签名快照当作服务端访问令牌。
